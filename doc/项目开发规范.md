# 项目开发规范

执行流程和 Git 授权规则遵循 [AGENTS.md](../AGENTS.md)。本文保留工程约束；接口、配置和接入示例分别维护在对应文档中。

## 范围与技术栈

支持 Jenkins、Alertmanager、Generic → 钉钉/飞书，提供 channel 路由、Token 鉴权及钉钉、飞书可选加签。渠道支持本地 YAML 或从 ops-agent-api 定时拉取，平台模式使用内存快照和YAML 恢复文件。不实现数据库、通知历史、管理后台、队列、发送重试或公司级发送权限。

使用 Go（版本见 `go.mod`）、Gin、`kit/log`、YAML、`text/template` 和标准库 `net/http`。新增依赖或组件必须说明用途、现有替代方案、构建部署影响及维护/安全风险，并获得确认；不得为少量功能引入大型框架。

## 分层

调用链：外部系统 → api → service → channel 配置 → sender → 通知平台。

| 目录 | 职责与边界 |
|---|---|
| `main.go` | 配置加载、依赖装配、服务启动 |
| `api/` | 解析参数、基础校验、统一响应；不编排发送或处理平台密钥 |
| `routes/`、`middleware/` | 路由、鉴权、请求日志 |
| `service/` | 来源转换、业务校验、channel 路由、模板选择与发送；不依赖 Gin 或处理 HTTP 响应 |
| `types/` | 请求、响应、配置和内部 DTO；不写业务或发送逻辑 |
| `pkg/` | sender、模板、脱敏、HTTP Client、错误码；不放来源转换/channel 业务，不依赖 api/service |
| `config/`、`templates/`、`doc/` | 配置示例、消息模板、项目文档 |

未确认数据库需求前，不创建 `repo/`、`model/`、`sql/`。

按语义命名：发送用 `SendXxx`，构造/渲染用 `BuildXxx/RenderXxx`，校验用 `ValidateXxx/validateXxx`，配置读取用 `ChannelStore.Get`，发送器创建用 `SenderFactory.New`；不套用 CRUD 命名。

## 发送与模板

- 输入来源适配放 service，平台适配放 `pkg/sender`；服务端维护 webhook、secret、模板和默认接收人。
- 平台渠道和最终接收人校验放 `service/channel_validation.go`；测试专用发送器、内存模板和装配辅助代码放各包的 `*_test.go`，生产保留统一依赖注入构造入口。
- Sender 提供 `Send(context.Context, Message) error` 和 `Platform() string`。Message 只包含平台无关的 `Title/Text/Level/Status/Color/At`，工厂只按平台创建发送器。
- 钉钉发送 Markdown，飞书发送 schema 2.0 卡片；两者均在 secret 非空时加签，为空时不加签，发送失败不降级重发。
- 平台成功判定与错误码遵循[接口文档](接口文档.md#通知发送结果)，不得把异常响应判为成功。
- 模板按 `<source>_<platform>.tmpl` 命名，只负责展示；业务判断在 service 归一化。模板公共能力只提供文件加载、渲染和时间函数，不开放任意系统资源访问。

## 接口、配置与安全

- 请求、响应及校验规则见[接口文档](接口文档.md)，配置字段与默认值见[配置说明](配置说明.md)，变更时同步更新。
- 业务错误由 service 返回，api 统一转换；错误码放 `pkg/e`。响应不得暴露内部配置、文件路径或堆栈。
- 默认开启通知鉴权，`/ping`、`/ready` 除外；支持 Bearer 和 `X-Webhook-Token`，Token 比较使用恒定时间比较。平台模式必须开启鉴权。
- 来源和连接配置由 YAML 管理，不展开环境变量；平台恢复快照使用明文 YAML，不要求额外加密密钥。渠道来源按模式选择，不合并或自动切换。不得提交真实 webhook、secret、Token 或其他敏感数据。
- 日志不得包含完整 webhook、secret、Token、Authorization 或平台原始敏感响应，只记录安全摘要。
- 通知请求使用统一截止时间，取消后不得启动后续发送；超时错误按接口文档返回。
- 当前日志含请求 method/path/status/cost、发送失败 channel/platform/status，以及平台同步和恢复文件状态变化的安全摘要；source、request_id 及鉴权失败等细分日志属于后续建议，不能视为已实现。

## 验证

| 变更 | 必须执行 |
|---|---|
| 纯文档 | `git diff --check` |
| Go 代码 | 对变更文件执行 `gofmt -w`，再运行 `go test ./...`、`git diff --check` |
| 依赖 | 额外运行 `go mod tidy` |
| 核心流程或复杂逻辑 | 额外运行 `go vet ./...` |

优先覆盖 channel 路由、Jenkins 校验、Alertmanager 转换、签名、payload、脱敏和鉴权的正常/异常/边界场景。外部平台使用 `httptest`，不依赖真实 webhook。验证失败先定位；若与本次修改无关，说明证据和影响。
