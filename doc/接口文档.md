# 接口文档

POST 请求使用 JSON，设置 `Content-Type: application/json`。channel 对应[服务端配置](配置说明.md)，客户端不传机器人 webhook 或 secret。

## 鉴权

除 `/ping` 和 `/ready` 外默认需要以下任一 Header：

```text
Authorization: Bearer <token>
X-Webhook-Token: <token>
```

同时提供时，非空 `X-Webhook-Token` 优先。仅配置 `auth.enabled: false` 时关闭鉴权。

## 通知发送结果

成功与失败响应示例：

```json
{"code":200,"message":"操作成功","data":{"channel":"ops-test","platform":"feishu","sent":true}}
```

```json
{"code":40001,"message":"channel is required","data":null}
```

| HTTP | code | 含义 |
|---|---|---|
| 200 | 200 | 成功 |
| 400 | 40001 | JSON/参数错误，channel 不存在或禁用 |
| 401 | 40101 | 鉴权失败 |
| 500 | 50001 | 模板、发送器或其他内部错误 |
| 500 | 50002 | 网络、平台 HTTP/业务错误或响应无效 |
| 503 | 50301 | 平台模式尚无有效渠道配置 |
| 504 | 50401 | 通知请求总处理时间超限 |

仅平台返回 HTTP 2xx、响应完整且不超过 4096 字节、JSON 有效、业务码明确为整数 `0` 才判成功。钉钉业务码为 `errcode`，飞书为 `code`；读取失败、空响应、业务码缺失/null/类型错误均判失败，错误仅返回安全摘要。

发送同步执行，无自动重试或去重。通知处理共享写超时 90% 的请求预算（默认 9 秒），超时返回 50401 并停止启动后续发送；已完成或在途通知无法撤回。失败或超时不保证平台未收到，调用方重试可能重复发送。以上格式不涵盖未知路由等框架默认响应。

## 健康检查

`GET /ping`，无需鉴权，仅检查 HTTP 服务：

```json
{"code":200,"message":"操作成功","data":{"message":"pong"}}
```

`GET /ready` 无需鉴权，返回当前渠道来源状态，响应禁止缓存：

```json
{"code":200,"message":"操作成功","data":{"ready":true,"mode":"platform","sync_status":"ok","persistence_status":"ok","last_sync_at":"2026-10-11T00:00:00Z","last_saved_at":"2026-10-11T00:00:00Z"}}
```

本地模式仅返回 `ready/mode`。平台模式出错时额外返回 `sync_error` 或 `persistence_error` 安全摘要，恢复成功后省略相应字段；不包含凭据、平台原始响应或内部路径。平台模式同步、持久化状态为 `pending/ok/error`，时间在尚无成功记录时省略。启动使用恢复文件时，`last_sync_at` 为文件记录的同步时间。无有效快照返回 HTTP 503、code 50301，仍包含状态数据；有效空快照返回 200。同步失败但有旧快照时保持就绪，使用 `sync_status` 和最后成功时间监控异常，避免以同步失败触发重启。

## Jenkins

`POST /api/v1/notifications/jenkins`

```json
{
  "channel": "jenkins-test",
  "status": "SUCCESS",
  "jobName": "demo-build",
  "buildNumber": "123",
  "buildUrl": "https://jenkins.example.com/job/demo-build/123/"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `channel/status/jobName/buildNumber/buildUrl` | string | 必填；构建号也需传字符串 |
| `services/imageRefs` | string[] | 服务名称、完整镜像地址 |
| `branch/commit` | string | 分支、提交摘要 |
| `deployEnv/packageType` | string | 环境、产物类型 |
| `deploy` | boolean | 可选；省略不展示，true/false 展示“是/否” |
| `deployType/triggerUser` | string | 部署方式、触发人 |

`status` 去空白、转大写后仅允许 `SUCCESS/FAILURE/ABORTED/UNSTABLE`。接收人使用 channel 的 `at`；调用示例见 [Jenkins 接入](Jenkins接入说明.md)。

## Alertmanager 通知

`POST /api/v1/alerts/alertmanager?channel=alert-prod&split=false`

使用 Alertmanager 原始 webhook JSON，`channel` 和非空 `alerts` 必填。仅 `split=true` 精确匹配时逐条发送，其余按合并处理。

```json
{
  "status": "firing",
  "groupLabels": {"alertname": "InstanceDown"},
  "commonLabels": {"level": "3"},
  "alerts": [{
    "status": "firing",
    "labels": {"instance": "demo:9100", "level": "3"},
    "annotations": {"summary": "实例不可用"},
    "startsAt": "2026-10-09T10:00:00Z"
  }]
}
```

- 标签、注解值均为 string；状态使用 `firing/resolved`，时间使用 RFC3339。
- `externalURL` 为控制台链接，`alerts[].generatorURL` 为详情链接，`endsAt` 为恢复时间。
- 拆分串行发送，遇错停止、不回滚。全部成功仍返回单个 `channel/platform/sent`，无数量或逐条明细。

告警规则、等级、颜色和接收人规则见 [Alertmanager 接入](Alertmanager接入说明.md)。

## Generic

`POST /api/v1/notifications/generic`

```json
{
  "channel": "ops-test",
  "title": "任务完成",
  "content": "备份成功",
  "status": "SUCCESS",
  "level": "info",
  "url": "https://example.com/tasks/1",
  "at": []
}
```

`channel/title/content` 必填；除 `at` 为 string[] 外均为 string。非空 `at` 覆盖默认列表，空数组或省略时沿用默认值。`ops-test` 需按[配置说明](配置说明.md)添加。

`content` 使用文本或 Markdown，网关不渲染或清洗 HTML；显示效果由平台决定。`level` 原样展示，不转换数字等级。

飞书颜色按 `status` 匹配（忽略大小写，不去空白）：`SUCCESS/OK/RESOLVED` 绿色，`WARNING/UNSTABLE` 橙色，`FAILURE/FAILED/FIRING/ERROR` 红色，其余蓝色。
